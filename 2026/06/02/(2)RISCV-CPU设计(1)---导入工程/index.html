一、导入阶段的输入与目标

导入阶段将门级网表、物理库和时序分析配置载入 Innovus，建立后续物理实现所需的设计数据库。主要输入包括实例及连接关系、单元尺寸与引脚几何、工艺规则，以及时序分析条件与约束。

1.1 输入文件及其作用

输入内容 作用 对应章节
综合后的门级网表 定义设计实例、连接关系与顶层模块 第五章
工艺 TLEF 定义工艺层、site、过孔和基本物理规则 第三章
标准单元 LEF、SRAM LEF 描述单元尺寸、引脚几何与布线阻挡 第二章（标准单元示例）
标准单元和 SRAM 的 .lib 提供相应 PVT 条件下的单元时序模型 见第四章的 library set
RC 提取工艺文件 提供互连寄生电阻、电容的提取依据 见第四章的 RC corner
SDC 约束文件 定义时钟、输入输出延时等时序约束 第四章（约束模式配置）
viewDefinition.tcl 把时序库、RC 条件和 SDC 组织成分析视图 见第四章

1.2 输入文件之间的关系

单元 LEF 描述具体单元的物理抽象，并引用工艺 TLEF 中定义的层、site 和过孔。viewDefinition.tcl 将 .lib、RC 提取条件和 SDC 关联为分析视图；1_run_import.tcl 则指定这些输入，通过 init_design 初始化工程，并执行网表检查与数据库保存。

二、单元 LEF：尺寸、引脚与布线阻挡

2.1 单元 LEF 和工艺 TLEF 的分工

物理库文件 LEF 描述单元的尺寸、引脚位置和布线阻挡，以及工艺的金属层和基本布线规则，是布局布线的基础输入。按描述对象可分为以下两类：

  • 工艺 TLEF：定义标准单元摆放用的 SITE，以及 LAYER、固定 VIA 和 VIARULE GENERATE 等工艺信息。
  • 标准单元 LEF、SRAM LEF：描述具体单元的大小、引脚和障碍物，并引用工艺 TLEF 中定义的层、site 或过孔。

2.3 RECT：矩形区域的坐标表示

RECT 是 Rectangle 的缩写。在 LEF 中，RECT x1 y1 x2 y2 ; 用左下角和右上角两个点描述一个矩形区域。单元内的图形坐标以本地坐标系为基准。

例如 RECT 0.485 0.125 0.535 0.755 ;，宽度是 0.535 - 0.485 = 0.050 µm，高度是 0.755 - 0.125 = 0.630 µm。一个引脚可包含多个 RECT，共同描述该引脚的端口几何形状。

代码 含义
SIZE 0.560 BY 0.900 ; 单元宽 0.560 µm、高 0.900 µm
SITE core ; 引用工艺 TLEF 中名为 core 的摆放格子
PIN Z、DIRECTION OUTPUT Z 是输出引脚；A1、A2 是输入引脚
PORT → LAYER M1 → RECT 描述引脚在 M1 上的几何形状

OBS → LAYER → RECT 描述相应层上需要避让的布线阻挡

2.5 CO 层的 OBS 阻挡

CO（Contact）是接触孔层，通常用于穿过绝缘层，将下方的有源区或多晶硅与第一层金属 M1 接通。LEF 中 CO 层的 OBS 表示该层需要避让的阻挡区域。

三、工艺 TLEF：摆放与布线规则

本章节选 Technology LEF 中的十组定义，说明其在布局布线中的作用。各小节标注的行号对应原始 TLEF 文件，代码中的 # … 表示省略内容。M1 层的完整规则片段见文末附录。

TLEF 提供布局布线使用的工艺定义。 单元 LEF 描述具体单元的外形、引脚和障碍物，并引用 TLEF 中定义的 site、层或过孔。

3.1 文件头：坐标单位、制造网格和扩展规则

原文件第 42–75 行。

  • BUSBITCHARS "[]" 用来表示总线位，例如 A[2]。DIVIDERCHAR "/" 给出层次分隔符。
  • DATABASE MICRONS 2000 表示 1 µm = 2,000 DBU，所以 1 DBU = 0.5 nm。MANUFACTURINGGRID 0.005 给出 5 nm 的几何对齐网格，相当于 10 DBU。
  • USEMINSPACING OBS OFF 让工具按 OBS 的实际形状计算间距。宽障碍物可以触发宽线间距规则。
  • PROPERTYDEFINITIONS 声明扩展属性。后面的 PROPERTY LEF58_SPACING "..." 会把具体间距规则写在引号里。这里的 MAXVIASTACK 4 NOSINGLE RANGE M1 M6 表示在 M1 到 M6 的范围内，叠超过四级时，该堆叠中的过孔都必须是多切孔过孔。

3.2 SITE core：标准单元放置 site

原文件第 77–81 行。

core 是核心区的标准单元放置 site，宽 0.14 µm、高 0.90 µm。标准单元 LEF 中的 SITE core ; 引用该定义。第二章示例中的 AN2D2BWP40P140 为 0.700 × 0.900 µm，对应 一行高、五个 site 宽。SYMMETRY Y 表示该 site 支持关于 Y 轴镜像。

3.3 四种非布线层：PO、CO、VTUL_N 和 OVERLAP

原文件第 107–127、1594–1596 行。

层及类型 含义
PO / MASTERSLICE 底层器件工艺相关的层，这里是多晶硅层的抽象。
CO / CUT 接触孔层。ENCLOSURE ABOVE 定义上方图形对切孔的包围量。
VTUL_N / IMPLANT 与器件阈值相关的注入层。文件中的其他 VT* 层采用类似定义。
OVERLAP / OVERLAP 可以配合宏单元的 OBS 描述实际摆放占用范围，例如直角多边形的宏占地。

3.4 LAYER M1：走线方向、轨道和线宽

原文件第 171–178 行。END M1 在第 268 行。

  • DIRECTION VERTICAL 表示 M1 的优选布线方向为竖直方向。竖线沿 Y 方向延伸，相邻两条竖向轨道在 X 方向隔 0.14 µm。
  • OFFSET 0.07 0.000 给出 X、Y 方向的起始偏移。按这组参数生成的竖向轨道可以落在 x = 0.07、0.21、0.35… µm。
  • WIDTH 0.05 是默认线宽，MINWIDTH 和 MAXWIDTH 给出线宽范围。

PITCH 表示相邻轨道的中心距，WIDTH 表示单根导线的宽度，SPACING 表示相邻导线之间的边到边间距。

3.5 M1 几何规则：面积、短边、平行间距和线端间距

原文件第 180–182、191–198、210–212 行。

  • AREA 规定最小金属面积。 对宽度为 0.05 µm 的独立矩形，仅考虑该基础规则时，长度至少为 0.0115 ÷ 0.05 = 0.23 µm。
  • MINENCLOSEDAREA 规定金属包围的最小孔洞面积。 本例中的下限为 0.2 µm²。
  • MINSTEP 约束轮廓中的短边。 本例限制连续短于 0.05 µm 的边最多为一条。
  • SPACINGTABLE 定义平行导线间距。 例如，两根导线的宽度分别为 0.20 µm 和 0.05 µm，平行重叠长度为 0.50 µm。按较大线宽选择 WIDTH 0.180 行，按平行长度选择 PARALLELRUNLENGTH 0.470 列，得到最小边到边间距 0.100 µm。
  • ENDOFLINE 定义线端间距规则。 第一条规则针对端边短于 0.070 µm 的线端，检查范围内要求间距 0.060 µm。WITHIN 0.025 描述沿线端两侧扩展的检查范围。第二条增加了平行邻边条件。

3.6 LAYER VIA1 和 MINIMUMCUT：切孔分类和数量

原文件第 270–275、337 行是切孔层节选，第 224–229 行是 M1 上的切孔数量规则。

  • LAYER VIA1 定义 M1 和 M2 之间的切孔层。VSINGLECUT 是 0.05 × 0.05 µm 的方孔。VDOUBLECUT 是 0.05 × 0.13 µm 的一个长孔，规则按两个 cut 计。
  • 以第一条 MINIMUMCUT 为例，宽度超过 0.18 µm 的 M1 导线或引脚向上层连接时，按切孔类别要求两个 VSINGLECUT，或一个 VDOUBLECUT。这里的 WITHIN 0.10 限定可合并计数的相邻切孔范围。
  • 带 LENGTH … WITHIN … 的规则还约束与宽线直接相连的细线。宽线满足宽度和长度条件时，细线上规定距离范围内的过孔也受约束。

3.8 VIARULE GENERATE：过孔阵列生成规则

原文件第 6120–6130 行。

固定 VIA 定义具体的过孔几何图形。VIARULE GENERATE 给出生成阵列时需要的切孔尺寸、孔阵列中心距、上下金属包围量和适用线宽。

这条规则的方孔宽度是 0.05 µm，X、Y 方向中心距都是 0.13 µm。因此，沿 X 或 Y 方向相邻的两个切孔，其边到边间距是 0.13 − 0.05 = 0.08 µm。VIAGEN12_RECT 使用长孔，与上述方孔生成规则构成对照。

3.9 M1 的 RC、天线、金属密度和电流密度

原文件第 234–236、238–239、243–246、264–266 行。

规则类别 含义
RC RPERSQ 是方块电阻，可用 R = R_s × L / W 估算导线电阻。另两项分别是单位面积和单位边长的电容系数。文件开头建议用 CapTable 或 QRC 获得更准确的 RC。

MMMC 是 Multi-Mode Multi-Corner，即多模式、多角时序分析配置。本脚本使用一个功能模式 cm_func，与四个 delay corner 组合，形成四个 analysis view。

4.2 第一步：创建四个 RC corner

rc_corner 定义互连的提取条件。工具结合互连几何信息、提取工艺模型、温度和缩放系数，得到寄生 R、C，再用于计算 net delay。

本脚本通过 -qx_tech_file 指定 QRC 的 qrcTechFile。阅读时应把它与 -cap_table 指定的 CapTable 文件区分开；这份脚本没有使用 -cap_table。QRC 文件与 RC corner 的关联方式可参考 Cadence 关于 QRC 工艺文件的说明。

4.3 第二步：创建四组 library set

library_set 定义用哪一组 .lib 时序库。这些库提供 cell delay、输出 slew，以及触发器 setup/hold 等时序模型。PVT 分别表示 Process、Voltage、Temperature，也就是工艺、电压和温度。

Library set 名称 库文件中的工艺标识 电压 温度 在本脚本中的用途
ssg_m40c ssg，慢角 0.81 V -40℃ setup
ssg_125c ssg，慢角 0.81 V 125℃ setup
ffg_m40c ffg，快角 0.99 V -40℃ hold
ffg_125c ffg，快角 0.99 V 125℃ hold

每组包含六个 .lib 文件：三份标准单元库（普通版本、LVT、HVT），以及三份 SRAM 库。同一组内的库文件按相应的工艺、电压和温度配套读取。 LEF 提供单元的物理抽象，.lib 提供时序模型，设计中用到的标准单元和 SRAM 都需要对应的模型。

delay_corner 把 library set 和 RC corner 组合起来：前者提供单元时序模型，后者提供互连提取条件。

Delay corner 名称 Library set RC corner

ffg_cbest_CCbest_125 ffg_125c cbest_CCbest_125

4.5 第四步：创建功能模式 constraint mode

该命令创建名为 cm_func 的功能模式，并读取 swerv_wrapper_syn_golden.mc.sdc。本脚本的四个 analysis view 均使用该模式，未定义独立的测试模式。

SDC 中的时钟、输入输出延时和时序例外共同定义该模式的时序约束。脚本中的 ../input/、../../library/ 均为相对路径，运行时应根据 Innovus 的当前工作目录核对。

4.6 第五步：创建四个 analysis view

analysis_view 关联 delay corner 和 constraint mode，从而为一个分析视图指定 .lib 单元时序模型、互连 RC 提取条件和 SDC 约束。

Analysis view 名称 Constraint mode Delay corner

4.7 第六步：分别启用 setup 和 hold 分析视图

创建 view 后，还需要用 set_analysis_view 指定哪些 view 用于 setup、哪些用于 hold：

  • Setup 启用两个视图：ssg、0.81 V，分别搭配 -40℃ 和 125℃ 的 cworst_T 提取条件。
  • Hold 启用两个视图：ffg、0.99 V，分别搭配 -40℃ 和 125℃ 的 cbest 提取条件。

Setup 分析检查数据到达是否满足建立时间要求，hold 分析检查数据变化是否满足保持时间要求。本脚本使用慢角组合进行 setup 分析、快角组合进行 hold 分析，两类分析均覆盖 -40℃ 和 125℃。

单元延迟由工艺、供电电压和温度共同决定，不能仅依据温度高低判定最大或最小延迟条件。 温度反转可能改变温度与单元延迟之间的关系，因此当前配置在 setup 和 hold 分析中均启用两个温度角。相关现象可参考 Cadence 对库模型与温度反转的说明。最差分析视图应根据实际库模型和时序报告确定；上述四个视图满足时序要求，并不代表未分析的其他组合也满足要求。

4.8 配置顺序与完整脚本索引

viewDefinition.tcl 的完整内容见文首“全文使用的脚本”章节。其配置顺序为 RC corner → library set → delay corner → constraint mode → analysis view → 启用视图。

五、设计导入：初始化、检查与保存

本章依据 1_run_import.tcl 的执行顺序，说明输入配置、设计初始化、网表检查与工程保存之间的关系。

5.1 1_run_import.tcl 的整体执行顺序

1_run_import.tcl 的完整内容见文首“全文使用的脚本”章节。本章按脚本执行顺序，解析每组输入设置和导入命令。

脚本的执行流程为：设置运行参数 → 指定输入文件和顶层 → 设置导入选项 → 初始化设计 → 检查并保存。

5.2 运行设置：阶段名、CPU 和设计名

语句 作用
set current_step "initial" 定义记录当前阶段名的 Tcl 变量，用于生成保存文件名 initial.enc
setMultiCpuUsage -localCpu 8 -cpuAutoAdjust true 设置本机 CPU 使用数为 8，并开启自动调整。具体步骤实际使用的并行数以工具日志为准
set design "swerv_wrapper" 定义供脚本引用的设计名变量；本段其余语句未使用 $design

design 为脚本自定义变量，初始化流程使用 init_top_cell 指定顶层模块。 当前脚本将两者分别赋值为 swerv_wrapper，修改 design 不会自动改变 init_top_cell。

5.3 物理输入：工艺 TLEF、标准单元 LEF 和 SRAM LEF

init_lef_file 指定初始化时要读取的物理库文件。该列表包含八个文件，分为以下三类：

类别 文件 提供的信息
工艺 TLEF，1 个 tsmcn28_10lm5X2Y2ZUTRDL.tlef site、工艺层、过孔及基本物理规则
标准单元 LEF，3 个 tcbn28hpcplusbwp40p140.lef、tcbn28hpcplusbwp40p140hvt.lef、tcbn28hpcplusbwp40p140lvt.lef 普通版本、HVT、LVT 标准单元的尺寸、引脚和阻挡
SRAM LEF，4 个 ts1n28hpcplvtb64x21m4sw_180a.lef、ts1n28hpcphvtb64x21m4sw_180a.lef、ts1n28hpcphvtb256x34m4sw_180a.lef、ts1n28hpcphvtb2048x39m8sw_180a.lef 相应 SRAM 宏单元的物理抽象

列表先指定工艺 TLEF，再指定单元 LEF，使工具先读取工艺层、site 和过孔等定义，再读取引用这些定义的单元。

大括号 {...} 将整个路径列表作为 set 的一个参数，路径行末的反斜杠 \ 用于续行。 该变量的值为包含八个文件路径的 Tcl 列表。

物理库与第四章的时序库需要配套核对：本脚本额外列入了 ts1n28hpcplvtb64x21m4sw_180a.lef，而第四章的 library set 仅列出 HVT SRAM 时序库。是否还需要这份 LVT SRAM 对应的 .lib，取决于网表是否使用了它。核对时应以网表的单元引用名、LEF 的 MACRO 名和 .lib 的 cell 名为准；多读入一份 LEF 本身并不能说明网表一定实例化了该单元。

5.4 逻辑输入：电源地、顶层和综合网表

变量 当前值 作用
init_gnd_net VSS 指定设计的地网络名称
init_pwr_net VDD 指定设计的电源网络名称
init_top_cell swerv_wrapper 指定网表中的顶层模块
init_verilog ../input/swerv_wrapper.v 指定要导入的 Verilog 网表文件

本流程读取综合后网表 swerv_wrapper.v，获取实例和连接关系。init_top_cell 应与网表中的顶层 module 名称一致。网表使用的标准单元、SRAM 等需要具有对应的物理库和时序库模型。

VDD、VSS 的设置声明了电源、地网络名称；后续还要按工程需要配置电源引脚连接与电源布线。相关区别可参考 Cadence 对初始化电源地网络与全局连接的解释。

5.5 时序输入：通过 init_mmmc_file 关联 viewDefinition

该变量指定第四章所述的 MMMC 配置文件，初始化流程通过该文件关联以下配置：

  • 四组 library set 中的标准单元和 SRAM .lib。
  • 四个 RC corner 使用的 QRC 提取工艺文件、温度和缩放系数。
  • 功能模式 cm_func 使用的 swerv_wrapper_syn_golden.mc.sdc。
  • 四个 analysis view，以及 setup、hold 各自启用的两个视图。

.lib 和 SDC 的读取配置位于 viewDefinition.tcl 中，由初始化流程统一载入时序分析环境。

运行时应根据 Innovus 的当前工作目录解析并核对相对路径，包括 import 脚本中的 ../input/、../scripts/、../../library/，以及 MMMC 文件内部引用的路径。脚本文件所在目录本身不能确定这些路径的解析结果。

5.6 导入选项：保留空模块

该设置要求导入时保留空模块，例如仅包含端口声明、不包含内部逻辑的模块。它控制空模块的导入处理，不会生成模块的功能逻辑，也不代替宏单元所需的 LEF 和时序模型。该选项可对照 Cadence《Innovus User Guide》中 Blackbox Flow 的说明。

该选项在 init_design 之前设置，以作用于本次网表导入。

5.7 执行 init_design：初始化设计数据库

set init_* 配置初始化参数，init_design 依据这些参数执行设计初始化。 这一过程把物理库、综合网表和 MMMC 时序环境关联起来，建立后续布局布线使用的设计数据库。

初始化使用的输入分为三类：

  • 物理信息：init_lef_file 指向工艺 TLEF、标准单元 LEF 和 SRAM LEF。
  • 逻辑信息：init_verilog 与 init_top_cell 确定网表及顶层，电源地变量指定相应网络名。
  • 时序信息：init_mmmc_file 关联 .lib、RC 提取条件、SDC 和分析视图。

初始化完成后，应检查导入日志，确认输入文件读取成功、顶层识别正确，以及网表单元与相应库模型匹配。

5.8 执行 checkDesign -netlist：检查导入后的网表

checkDesign 用于检查设计数据，-netlist 选择网表相关的检查。该检查在 init_design 之后执行，针对已导入的网表进行基础检查；具体检查项和诊断以当前工具版本的输出为准。命令用途可参考 Cadence 的 checkDesign 使用说明。

这一阶段结合导入日志，重点核对单元引用、实例与引脚的对应及连接异常等问题。SDC 的完整性和各视图下的时序结果，后续还需要分别检查。

该脚本在网表检查命令之后直接执行保存命令，未根据检查结果设置条件分支。因此，执行保存命令本身不能证明检查通过，应确认检查输出中的错误和警告已得到处理。

5.9 执行 saveDesign：保存 initial 阶段工程

current_step 的值为 initial，因此变量展开后的保存路径为：

saveDesign 保存当前的 Innovus 设计状态，供后续 floorplan 等物理实现步骤继续使用。保存前应确认 ../save/ 目录已创建；若工具生成配套的数据目录或文件，备份、移动工程时应一并保留。
